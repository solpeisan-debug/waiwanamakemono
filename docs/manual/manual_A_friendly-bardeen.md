## 4. 波形の作り方（技術の中身）

- 【技術】拍の部品は関数（`p_sinus`・`qrs_normal`・`qrs_pvc` など。ガウス関数の足し合わせ）。`KINDS` に（QRS関数, P関数, PR）を登録
- 【技術】パターンは `PATTERNS` に `no, name, col, hint, one, tag, ev, L, art, gain, hl`。`ev`＝1周期の拍（時刻, 種類）、`L`＝周期、`art`＝連続波形（細動波・VF・ノイズ）、`gain`＝倍率、`hl`＝色を付ける範囲
- 【技術】連続波形は周期 L でくり返すよう、周波数を 1/L の整数倍にした帯域ノイズ（`band_noise`）。**乱数の種を固定**して毎回同じ形にする
- 【注意】乱数でできた細動波が、QRSの直前で P波に似たこぶになることがある（第24弾 ⑤ でレビュー指摘）。種や周波数を変えて消す
- 【技術】区間の切れ目は「拍の並びがくずれない位置」で決める（R-R・P-P がつなぎ目でおかしくならない）。`--check` でつなぎ目の間隔を表示して確かめる
- 【技術】**その場で形が変わる（モーフ）**（第25弾で作り、第24・26弾に広げた。2026-10-10〜13）
  - 形の段階を**時刻だけで決まる** `s(t)` にする。画面に見えている拍が全部同時に同じ形に変わる
  - 形は**数値（山の高さ・位置・幅・PR・QRS幅など）を補間**する。波形どうしを重ねて混ぜると、山が2つに割れる
  - 拍の位置は「中央を通った拍の数を積み上げた位相」から決める → 拍の間隔が変わっても、拍が跳ぶ・消える・増えることがない
  - 名前・ひとこと・声が出ているあいだは、そのパターンの形そのもの。形が変わるあいだは声を入れない（`align_vo.py` で確かめる）
  - 紹介が終わったら**写し（コピー）だけ**が縮んで枠へ飛ぶ。帯は消えない
- 【決まり】**つなぎ目のルール（2026-10-14 ユーザー承認）**：その場で直接変えるのは**同じ病態の中だけ**（例：高K の進行、心房細動どうし、粗動の伝導比）。それ以外は**うすい灰色の「ふつうの洞調律 75/分」**を一瞬通し（0.6〜0.7秒で変わる・0.3〜0.5秒そのまま・0.6〜0.7秒で次へ）、「▶ 次の例」と小さく出す。理由：AI専門医が「ある不整脈が別の不整脈に移るように見える」と指摘したため（例：多源性心房頻拍→心房細動→粗動は実際に起こる移行に見える。サイン波→正常は「自然に治る」と読まれる）。サイン波→次は、先に薄く消してから灰色を出す（「▶ 次の例（別の病態）」）
- 【技術】心拍数カウンター「♥ ◯/分」：1拍ごとに R-R から計算、拍で光るハート。不規則なリズムでは「1拍ごとの値（モニターは平均）」と注記。形が変わるあいだは「--」。休み（ポーズ）のあいだも「--」。波形と重なるときは暗い板を後ろに敷く（第24弾 `make_reel24.py` の `draw_heart`、第26弾）
- 【技術】PQRST の文字（第25弾）：拍にくっついて流れ、R頂点が画面の x 210〜870 にある拍だけに付ける。色 P黄・Q水色・R白・S黄緑・T橙、U はピンク
- 【技術】ゴースト：基準の拍を白っぽくうすく重ねて「どこが変わったか」を見せる（第25弾）。P波がない場面ではゴーストのP波も消す（レビュー指摘）
- 【技術】キャラクター（第21弾 v3/v4、保留中）：`reel21_v4/characters.py`。顔がこぶの中に線にふれずに入るかを毎コマ計算し、入らなければ描かない。`--check` で全編0.1秒ごとに確かめる
- 【技術】密集した速い波形（VT・VF・トルサード）は、モニターの「一時停止（⏸）」で止めて見せると目が疲れない（第21弾 v4）

## 10. はまりどころ・失敗と対策（まとめ）

- 【注意】通常版をラベルなしで送り、ユーザーがそのまま投稿した → 送るときは毎回「通常版」と書く
- 【注意】`cut()` のバグで語尾が切れた（第6章）
- 【注意】rubberband で声の高さが変わった → atempo
- 【注意】AI専門医とユーザーの方針がぶつかることがある（例：第21弾で専門医は「医師へ報告」を足したがったが、ユーザーは書かない方針）。**ユーザーの方針を優先**し、Gemini への引き継ぎにも書いておく
- 【注意】キャプションの数（「3枚」）など、まだ出していないものを先に書かない（見分けマップ②で注意された）
- 【注意】モーフで「病態が移る」ように見える問題（第4章のつなぎ目ルール）
- 【注意】速く密集した波形が大きく流れると目が回る（一時停止で対処）
- 【注意】並行して複数のエージェントが同じブランチにコミットすると、互いの途中の変更が他人のコミットに入る。`git add -A <自分のフォルダ>` だけにし、push が弾かれたら `git pull --no-rebase` してから push
- 【注意】stop フックが「未コミットの変更」を指摘する → こまめに commit・push
- 【注意】`pkill -f` は使わない（セッションを壊すことがある）
